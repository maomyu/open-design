# 爆创(WorkBuild 自媒体爆款监控系统)· 常见报错排查手册

> 交付对象:煜之禾团队(非技术使用者) · 版本对应:打包安装版 mac dmg(BUILD 47+)
> 用法:遇到异常,先在「故障速查表」里找到你看到的现象,点进对应条目,照「分步修复」做即可。
> (本手册每个故障、报错文案、命令名、字段名均取自真实代码与验收测试记录,非假设场景。)

---

## 开篇必读:三条底层常识(先懂这个,排查不慌)

1. **系统"失败不丢任务"是设计好的**。任何一步出错,系统不会崩、不会丢数据,而是:①把这条任务放进「失败队列」;②在飞书「发布复盘库⑤」写一行**错误摘要**;③继续跑后面的任务。所以你看到"错误摘要"、或采集少了几条,**不代表系统坏了**,代表某条任务遇到了可修复的小问题。

2. **出问题第一时间看这三个地方**:
   - **① 应用「账号页 → 运维卡片 → 失败队列」**:直接显示失败原因,旁边有「重跑」按钮。
   - **② 飞书「发布复盘库⑤」的「错误摘要」列**:失败原因写在飞书里,不碰电脑也能看到。
   - **③ 真抓爆款采集后,界面若出现红字"未同步飞书"**:说明这次数据没写进飞书(多半是飞书连接问题,见故障1)。

3. **每个能力都有两个入口:界面按钮 + 命令**。平时用界面按钮就行;命令(`od baokuan …` 开头)用于高级自查/开发方远程指导,本手册会一并给出。

## 故障1 · 飞书数据中心不同步 / 采集 0 条写不进飞书

**现象**:采集能出选题结果,但飞书 10 张表里**没有新增行**;或采集后界面出现**红字"未同步飞书"**。

**可能原因**:飞书写入靠 **lark-cli** 连接工具。它**没连上飞书账号**,或应用从访达双击启动时**找不到它**(系统只给了最小环境)。真实测试复现过:找不到 lark-cli → 系统**静默跳过写飞书、只出选题**。新版已补红字提示、并把工具打进安装包。

**去哪看原因(检索关键字)**:界面红字"未同步飞书"(来自 `feishu_synced: false`);日志搜 **`飞书数据中心暂不可用`**,完整形如
`[radar] 飞书数据中心暂不可用(未连接/未建表)，本轮跳过回写、只产出选题：FileNotFoundError: 'lark-cli'`。出现 `FileNotFoundError: 'lark-cli'` = 找不到工具;报权限码 = 授权掉了。

**分步修复**:
1. 完全退出应用(⌘Q)重新从"应用程序"打开(新版重启大概率自动恢复)。
2. 重启后再采集一次,看红字是否消失。
3. 仍不同步 = 飞书授权掉了,**联系开发方**重新授权 lark-cli(账号登录类不建议自行盲操作)。
4. 确认飞书目标 base 和 10 张表没被删。

**验证已修复**:再采一次不再出红字;飞书选题池②/原始库①能看到刚采的新行。

## 故障2 · 真抓爆款"采到 0 条"或条数很少

**现象**:采集结果 0 条或很少;定时任务某关键词 `candidates` 是 0。

**可能原因**:①门槛设太高+关键词冷门(`--min-threshold 999999` 就是故意采 0);②TikHub Key 余额用完/网络不通;③平台名填错(老版本;新版已修中英文都认);④关键词太窄本身没内容。

**去哪看原因**:界面显示"按【某档】采到 N 条"= 门槛/关键词问题非故障;日志搜 **`采集失败`**(通道问题)或 **`[自动降档] 命中档位`**(正常放宽);命令 `python scripts/check_keys.py` 看 `TikHub` 那行 ✅/❌。

**分步修复**:
1. 门槛调低或清空——系统内置**自动降档**(大爆款→爆款→热门→小热→取头部),平台上有内容基本不会真 0 条。
2. 换更大众的关键词再试。
3. `python scripts/check_keys.py` 若 `TikHub ❌` 或 401/403 = Key 过期/欠费,充值换 Key(联系开发方改 `.env` 的 `TIKHUB_API_KEY`)。
4. 小红书注意图文/视频:图文台只采图文,别在图文台找视频爆款。

**验证已修复**:大众词+低门槛能返回多条带评分候选。

## 故障3 · 小红书单链接内容对不上 / 提示改用关键词采集

**现象**:小红书单链接跑出来的内容**和你贴的对不上**(贴"脱单"却拆出"跑步减肥"),或直接报错让你改关键词采集。

**可能原因**:小红书接口**已知限制**——按 id 取详情常返回"推荐流"(别的笔记)而非本条。系统已做**保护**:发现不是本条就**主动拒收、绝不写错内容进飞书**。其余 5 平台单链接正常,**仅小红书**有此限制。

**去哪看原因**:报错文案明确写
`小红书单链接取详情失败:该链接取不到本条(小红书 detail 常返回推荐流,需带 xsec_token 的分享链接);小红书建议改用关键词采集 od baokuan collect`;日志搜 **`判为推荐流,丢弃`**(系统拒收=正确行为)。

**分步修复(换正确姿势,非修坏)**:
1. 小红书改用**关键词采集**(输入主题词,搜索结果内容准还自带原文原图)。
2. 一定要针对某条,用**带 `xsec_token` 的完整分享链接**(App"分享→复制链接"),但仍建议优先关键词。
3. 其他平台单链接照常用。

**验证已修复**:关键词采集这条主题,选题池标题/原文与你要的一致。

## 故障4 · 脚本里只有标题,没有口播文案(转写为空)

**现象**:拆解/脚本内容单薄像只根据标题写;"原视频文案"字段空。

**可能原因**:①`ASR_API_KEY` 空或"待填"→转写跳过;②视频太长超时(新版已按时长自适应,极长仍可能);③视频本身无口播(纯音乐/卡点,转写空是正常);④个别视频防盗链拉不到音频。

**去哪看原因**:日志搜 **`ASR 转写跳过`**;`od baokuan cost` 里 `asr` 调用次数一直是 0 = 转写从没成功,优先怀疑 Key。

**分步修复**:
1. 让开发方确认 `.env` 的 `ASR_API_KEY` 有效(非空/非"待填")——最常见原因。
2. 测试用 1–3 分钟有口播的短视频,别用 20 分钟长视频。
3. 纯音乐/无口播视频转写空是正常,系统用标题继续跑。

**验证已修复**:有口播短视频跑单链接,"原视频文案"出现大段真实口播(真实测试:87 秒视频转出 592 字)。

## 故障5 · AI 脚本/拆解生成失败(进失败队列)

**现象**:某条任务在生成脚本/拆解这步失败,进失败队列;复盘库⑤出现"错误摘要"行。

**可能原因**:文本创作靠 **DeepSeek**。失败几乎都是 Key 过期/余额不足/服务抖动。系统有**自动兜底**:主模型失败**自动切备用模型重试**,主备都失败才入队。

**去哪看原因**:飞书复盘库⑤「错误摘要」列;日志搜 **`主模型 … 失败 … 切备用 … 重试`**(触发保护)或 **`[失败队列] #… 已入队`**;命令 `python scripts/check_keys.py` 看 `DeepSeek` ✅/❌。

**分步修复**:
1. `python scripts/check_keys.py` 确认 `DeepSeek`。
2. `DeepSeek ❌` = Key 过期/欠费,充值或换 Key(联系开发方改 `.env`)。
3. 修好后进运维卡片点**「重跑」**或 `od baokuan retry`。
4. `DeepSeek ✅` 却偶发 = 服务抖动,等几分钟重跑。

**验证已修复**:重跑后任务成功,飞书审核库④出现新脚本。

## 故障6 · 封面能出但"参考封面"风格分析不准

**现象**:新封面配色只是大致跟参考图主色调,没"看懂构图再模仿";中文标题本身准确(不错字)。

**可能原因**:"看懂参考图"需**火山方舟视觉理解模型**,而**你的方舟账号目前一个视觉模型都没开通**(真实测试:126 个模型逐一探测,视觉类全 404)。系统**自动降级**为提取主色配色,封面照出、标题照准——只是少了"深度看懂"这层。**能力档次问题,不是坏了**。

**去哪看原因**:analyze 返回 `"来源"` 字段:`"vision"`=用上视觉模型;`"palette"`/`"default"`=降级(`降级原因` 常含 **`404`** 或 **`未配置 VISION_MODEL/ARK`**);搜 **`InvalidEndpointOrModel`** = 模型没开通。

**分步修复(一次性,开通即永久升级)**:
1. 登录**火山方舟控制台**。
2. **开通任意一个 doubao 视觉理解模型**(如 `doubao-1.5-vision-pro`)——控制台一键开通。
3. **无需改配置**:`.env` 已预置 `VISION_MODEL` 且有防呆,开通后自动升级。
4. 不需要这层深度解析可不管——降级模式在验收里达标。

**验证已修复**:再跑 `od baokuan cover analyze --ref <图>`,`"来源"` 变 **`"vision"`**,给出构图/色彩/情绪。

## 故障7 · 封面图/背景生成失败或只出纯色底图

**现象**:背景图出不来,或是一张纯色渐变底(非 AI 生成场景图)。

**可能原因**:背景靠**火山方舟 Seedream 生图模型**。ARK Key 没配/过期/余额不足时系统**自动退化为渐变底图**(保证封面永远能出、标题清晰),不报错崩溃。

**去哪看原因**:`python scripts/check_keys.py` 看 `火山Ark` 行;`od baokuan cover gen` 返回背景明显纯色 = 无 Key 退化。

**分步修复**:
1. `python scripts/check_keys.py` 确认 `火山Ark`。
2. 不可连:查 ARK 余额,确认 `.env` 的 `ARK_API_KEY`/`ARK_API_BASE`/`IMAGE_MODEL` 有效(联系开发方)。
3. 确认方舟**生图模型 `doubao-seedream` 已开通**(注意:与故障6 的"视觉理解模型"是**两个不同模型**,一个画背景一个看参考,可能需分别开通)。
4. 修好后重新生成。

**验证已修复**:重新生成,背景变真实 AI 场景图,标题准确不溢出。

## 故障8 · 定时任务到点没自动跑

**现象**:以为会定时自动采集,到点没动静,飞书没新数据。

**可能原因**:①**根本没配定时触发器**——自动采集命令是 `od baokuan scheduled`,但"每隔多久跑"需 cron/开机自启触发;②飞书「监控配置库⑥」监控项**没勾"启用"**(禁用行会被正确跳过);③开机自启没开;④命令行找不到 `od`。

**去哪看原因**:手动跑 `od baokuan scheduled`——返回 `{"runs":[]}` = 没启用项;有 `candidates` 数 = 调度本身通,只是没自动触发。`od baokuan autostart status` 看 `enabled`。

**分步修复**:
1. 飞书「监控配置库⑥」把要监控的行**勾"是否启用"**(界面账号页"定时监控卡片"也能增删改)。
2. 开开机自启:运维卡片开关或 `od baokuan autostart on`。
3. 配定时:让开发方用系统 cron 定时调 `od baokuan scheduled`(如每 2 小时);交付时通常已配好。
4. 随时可自己敲 `od baokuan scheduled` 立即跑一轮,不用等定时。

**验证已修复**:`od baokuan scheduled` 返回启用项都跑了有候选;`autostart status` 显示 `enabled: true`;到下个定时点飞书选题池自动多行。

## 故障9 · 应用刚装好/刚更新后第一次特别慢、像卡住

**现象**:全新安装或刚更新后,第一次用功能转圈很久像卡死(1–5 分钟)。

**可能原因(正常一次性过程)**:系统内置 Python 引擎,**第一次用到它时后台自动"装环境"**(解压运行时、建虚拟环境、离线装依赖),只在首次(或大版本更新首次)发生,需几分钟。装完后每次秒开。

**分步修复**:
1. 第一次用请**耐心等几分钟**,别反复强退(强退可能打断装环境反而更慢)。
2. 等它转完一次再正常使用。
3. **超过 10 分钟**仍无反应:⌘Q 退出重开再给一次机会;仍不行联系开发方(可能安装包不完整或磁盘空间不足)。

**验证已修复**:首次跑完后再点同一功能变秒级响应。

## 故障10 · 失败队列攒了一堆任务

**现象**:运维卡片失败队列或 `od baokuan failed` 列了好几条。

**可能原因**:"失败不丢任务"的正常表现——某段时间 Key 过期/网络差/额度用完,期间任务被安全存队列等重跑。根因通常是故障 4/5/7 的某个 Key/额度问题。

**去哪看原因**:界面/命令 `od baokuan failed` 每条带原因,如
`#1 [link] RuntimeError: 详情返回空数据(无内容ID),aid=999…`。看 `[…]` 类型(link/keyword/account/candidate/regenerate)判断根因属哪个故障。

**分步修复**:
1. **先解决根因**(对照故障 4/5/7 修 Key/额度)——根因没修别急着重跑,否则再失败。
2. 修好后点**「重跑」**或 `od baokuan retry`(默认一次 5 条,可 `--limit 10`)。
3. 系统重跑**不重复入队**(仍失败的留原位不越滚越多),可放心多点。
4. "注定失败"的(如无效假链接)会一直留队列按设计再失败,可忽略或让开发方清掉。

**验证已修复**:点「重跑」后 `od baokuan failed` 条数变少或清空,对应成品在飞书出现。

## 故障11 · 某功能菜单不见了 / 提示"功能未授权"

**现象**:某平台或能力入口不见了,或点了提示未授权。

**可能原因**:WorkBuild 用**签名授权文件(license)**控制每客户开通哪些功能。你的包(煜之禾·鱼老师版)开通:短视频全平台 + 公众号 + 小红书图文 + 飞书数据中心 + 个人知识库 + 全部 AI 能力。授权文件过期/误删/版本不匹配时相关功能被隐藏。

**去哪看原因**:成套功能突然消失(不是单按钮报错)通常是授权问题。

**分步修复**:
1. 授权涉及签名和账户,**不建议自行改动**,把"哪些功能不见了"截图给**开发方**。
2. 开发方重新签发授权文件,按指引导入(或放指定数据目录后重启)恢复。
3. 已采集/生成的数据都在,不会丢。

**验证已修复**:导入新授权并重启后,消失的菜单重新出现。

## 附录① · 日志在哪、怎么看(从简到专业)

1. **飞书「发布复盘库⑤」「错误摘要」列**(最省事):任务失败原因都在这里,搜复盘结论含 **"任务失败"** 的行。
2. **应用内失败队列**:账号页→运维卡片→失败队列,带原因+一键「重跑」。
3. **采集界面红字**:出现"未同步飞书"=飞书连接问题(故障1)。
4. **一键连通自检**(判断哪个 Key 坏了,最有用):引擎目录运行
   ```
   python scripts/check_keys.py
   ```
   逐项打印 ✅通 / ⬜未配置 / ❌报错(带原因),覆盖 飞书/TikHub/DeepSeek/火山Ark/极致了。
5. **详细日志文件**:打包应用日志文件名 **`latest.log`**,在应用数据目录 `logs/daemon/` 下;引擎数据(去重库/成本台账/失败队列)在引擎 `data/`(`data/cache.sqlite`),封面在 `data/covers/`。需要翻这些时,直接把数据目录或 `latest.log` 打包发开发方。

**给开发方反馈时最有用三样**:①现象截图;②`python scripts/check_keys.py` 输出;③`od baokuan failed` 输出。

## 附录② · 常用自查命令

> 这些都是只读或安全操作,不会弄坏数据。`od baokuan …` 走界面同一套后端。

| 目的 | 命令 | 看什么 |
|---|---|---|
| 看各平台 Key 通不通 | `python scripts/check_keys.py` | ✅通/⬜未配置/❌报错 |
| 看近 7 天成本 | `od baokuan cost --days 7` | LLM tokens/ASR 次/图像张/TikHub 次,按天 |
| 看失败任务和原因 | `od baokuan failed` | 每条类型+报错原因 |
| 重跑失败任务 | `od baokuan retry --limit 5` | 修好根因后再跑 |
| 立即手动跑一轮定时采集 | `od baokuan scheduled` | 返回 `{"runs":[]}`=没启用项 |
| 看开机自启是否开着 | `od baokuan autostart status` | `enabled: true/false` |
| 备份全部数据 | `od baokuan backup` | 生成 tar.gz,拷走即迁移 |

**`od baokuan cost` 的妙用**:某类调用次数长期 0 往往就是那项没配通——`asr` 一直 0→转写 Key 没配(故障4);`llm` 一直 0→DeepSeek 没配(故障5);`image` 一直 0→封面生图没配(故障7)。
