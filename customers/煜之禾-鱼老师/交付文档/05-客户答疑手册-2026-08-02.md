## 2. 服务商与计费对照

系统涉及五类服务,账户相互独立,余额互不相通。

| 服务商 | 承担环节 | 充值入口 | 余额查询 |
|---|---|---|---|
| TikHub(tikhub.io) | 抖音、小红书、B站、快手、视频号的搜索、详情、评论采集;按次计费 | tikhub.io 用户后台 | tikhub.io 用户后台 |
| 极致了(dajiala.com) | 公众号搜一搜、爆文榜、类目账号榜、文章数据;按次计费,约 0.02–0.5 元/次 | dajiala.com 用户后台 | dajiala.com 用户后台 |
| 火山方舟 Ark(console.volcengine.com/ark) | 封面图生成(Seedream) | 火山引擎控制台 → 费用中心 | 同左 |
| 火山语音(console.volcengine.com/speech) | **视频口播转写(ASR,洗稿的原料)**。注意:与上面的方舟是两套服务、两把 key,方舟的 ark-\* key 在语音接口无效 | 火山控制台 → 语音技术 → 大模型录音文件识别,开通后获取 API Key | 同左 |
| DeepSeek(platform.deepseek.com) | 备用文本模型,仅在本地 CLI 不可用时启用 | platform.deepseek.com | 同左 |
| 本地 CLI(如 Claude Code) | 选题评分、爆点拆解、脚本与文章生成的主用 AI | 不按 token 计费,使用 CLI 自身订阅;在终端登录一次即可 | 不适用 |

余额类报错自本版本起标注服务商名称与充值地址。示例:

> 爆文榜:金额不足,请充值(这是「极致了/大家来」dajiala.com 的账户余额,跟 DeepSeek/火山方舟等 AI 余额无关——去 https://www.dajiala.com 后台充值)

此前反馈中"提示余额不足但 DeepSeek 尚有余额"的情况,实际欠费方为极致了账户;旧版本报错未标注来源,已修正。

## 3. 命令行工具(od)的使用

### 3.1 定位

日常操作在界面内完成,不依赖命令行。od 命令行用于自动化调度、批量任务与远程维护,与界面调用同一套接口,功能等价。

| 命令 | 界面等价操作 |
|---|---|
| `od baokuan collect --keyword <词> --platforms <平台>` | 创作页「真抓爆款」 |
| `od baokuan scheduled` | 监控配置库启用后,调度器自动执行的巡检 |
| `od baokuan link <url>` | 单条链接完整处理(采集、拆解、脚本、复盘) |
| `od baokuan cost [--days N]` | 成本统计(LLM/采集/ASR 调用量) |
| `od baokuan failed` / `od baokuan retry` | 失败任务查看与重跑 |
| `od baokuan backup` | 引擎数据与配置备份 |
| `od studio ...` | 创作台全部能力(选题、写作、发布等) |

全部子命令支持 `--json` 输出,便于脚本处理。完整清单执行 `od baokuan help`、`od studio` 查看。

### 3.2 在安装版上执行(已验证)

安装包内置命令行入口,无需单独安装 Node.js。前提:应用处于运行状态(后台服务随应用启动)。

**Windows**(cmd 中执行;安装目录以实际为准,默认 `%LOCALAPPDATA%\Programs\WorkBuild`):

```bat
set OD_SIDECAR_IPC_PATH=\\.\pipe\open-design-baochuang-daemon
set ELECTRON_RUN_AS_NODE=1
"%LOCALAPPDATA%\Programs\WorkBuild\WorkBuild.exe" "%LOCALAPPDATA%\Programs\WorkBuild\resources\app\prebundled\daemon\chunks\cli-R4TPITBC.mjs" baokuan cost --json
```

**macOS**:

```bash
export OD_SIDECAR_IPC_PATH=/tmp/open-design/ipc/baochuang/daemon.sock
ELECTRON_RUN_AS_NODE=1 "/Applications/WorkBuild.app/Contents/MacOS/WorkBuild" \
  "/Applications/WorkBuild.app/Contents/Resources/app/prebundled/daemon/chunks/cli-R4TPITBC.mjs" \
  baokuan cost --json
```

说明:`cli-*.mjs` 文件名随版本变化,以 `chunks` 目录下实际文件为准。上述调用已在本次安装包上实测,返回正常 JSON。

### 3.3 日志位置

- 界面:采集与 AI 任务的结果、报错直接显示在对应页面,报错文案包含原因与处理指引。
- 文件(供维护排查):`C:\Users\<用户名>\AppData\Roaming\WorkBuild\namespaces\baochuang\logs\daemon\latest.log`(Windows);macOS 位于应用数据目录同名路径。

### 3.4 基础排查顺序

1. 完全退出应用后重新启动(含托盘进程);
2. 依据报错标注的服务商,到对应后台核对密钥与余额;
3. 设置 → 媒体生成,确认各项密钥无缺失、无多余空格;
4. 仍无法定位时,提供报错截图与发生时间,由维护方查日志定位。

## 4. 短视频洗稿流程

本项为此前反馈的核心缺陷("只能读取标题,AI 从零开始写"),已修复并实测。

### 4.0 手动添加选题(2026-08-04 起简化)

候选选题不止来自「真抓爆款」,也可以手动添加,现在只需一步:在创作页底部「添加选题」区**粘贴原文链接**(手机分享出来的短链如 `v.douyin.com/xxx` 直接可用,抖音/小红书/快手/B站/公众号均支持)→ 点「识别」→ 标题、来源自动填好,原文案与原图一并带回 → 点「添加」。切入角度选填,AI 会按填写的角度写。识别失败时会说明原因,仍可手动填标题后添加。

### 4.1 流程

1. 在候选选题中选择一条带原文链接的条目(采集或手动添加的均可),点击「去创作」;
2. 系统自动下载原视频并转写口播。**页面顶部全程显示进度条**:「原视频下载中」→「正在转写口播文案…已等待 N 秒」→「已转写(N 字)」;无口播或失败同样在顶部明示原因。右侧「原文案」标签页可查看转写全文,其中的「提取口播文案 / 重新提取」按钮可随时手动触发;
3. 点击「AI 写脚本」。生成逻辑固定为四步:
   - 提取原视频口播中的观点与信息点;
   - 保留观点内核,更换表达方式重写(更换例句、比喻、句式,不复制原句);
   - 依据「补充要求」中的提示词,追加原视频没有的新观点(1–3 个);
   - 将改写内容与新观点按逻辑衔接为完整口播稿。
4. 需要加入自有观点时,写入「按我说的改」/补充要求输入框,例如:"补充一个观点:发型比穿搭见效更快;再加入理发店沟通话术"。

### 4.2 转写能力说明(实测)

前置条件:在「设置 → 媒体生成 → 火山语音(ASR 口播转写)」填入火山**语音技术**的 API Key(见第 2 节,与方舟 key 不通用)。未配置时转写为空,系统会以视频标题/简介兜底,洗稿效果打折。

- 教程、口播类视频:实测一条"男生伪素颜教程"视频,完整转写 1413 字口播文案,可直接作为洗稿素材。
- 台词较少的视频:转写结果相应较短,仍会注入生成流程。
- 纯音乐、无人声视频:无口播即无文字可提取,此时 AI 依据标题与切入角度生成。属素材本身限制,更换含口播的原视频即可。
- 报错语义:出现「连不上火山语音服务」表示连续 3 次网络请求失败(单次网络抖动会自动重试,不会报错),报错中附带底层原因;此时检查本机网络后重试即可。

### 4.3 公众号洗稿

选题带原文链接时,点击「去创作」自动取回原文正文(提示"已取回原文"),文章生成按同一"提取观点 → 改写 → 补充新观点 → 衔接"流程执行。

## 5. 术语说明

**切入角度**:同一选题的写作视角,会注入 AI 提示词(本版本起生效)。示例,选题同为「男生变帅」:

| 切入角度 | 产出方向 |
|---|---|
| 从发型入手的低成本变帅 | 发型攻略 |
| 过度护肤反而毁脸 | 避坑、反常识 |
| 择偶标准悖论 | 情感共鸣 |

不填写时由 AI 自行确定;填写后按填写内容执行。

**最低阈值**(监控配置库):内容热度(播放/阅读量)下限,低于该值的内容不采集。0 或留空表示不限制。

**时间窗**(监控配置库):仅采集该时间范围内发布的内容。`7d` 即最近 7 天,`30d` 即最近 30 天。
公众号爆文榜数据源单次查询上限为 7 天跨度,系统自动分段合并,时间窗选择"近半年"亦可正常返回(旧版本该场景返回 0 条,已修复)。

**检测频率**(监控配置·系统配置表,配置项名"检测频率"):自动巡检的执行间隔,单位分钟,默认 120。修改后下一轮生效。

## 6. 监控配置与创作页搜索的关系

两个入口,分工如下:

- **创作页「真抓爆款」**(手动):按页面当前勾选的筛选条件执行。
  - 四个档位均不勾选 = 自动降档模式:系统按标准从严到松逐级匹配,最终兜底放宽至不限时间,冷门关键词也会返回相对最优结果。此前"全不勾选也返回 0 条"的缺陷已修复(另一成因为 TikHub 密钥失效,见第 1 节)。
  - 勾选任意档位 = 手动模式:严格按勾选条件筛选,不降档。冷门关键词建议不勾选档位。
- **监控配置库**(自动):作用于定时巡检。巡检结果写入数据中心「今日爆款选题池」,并自动同步至创作页候选选题列表,可直接「去创作」。此前"监控到的内容无处操作"的问题由此解决。

## 7. 「AI 帮我选题」输出异常的说明

此前反馈"输出无可复制标题且提示余额不足":当时 AI 调用数据接口遭遇极致了账户余额不足,产出降级。本版本两点变更:

1. 余额类报错标注服务商与充值地址(见第 2 节);
2. 选题产出统一落入「候选选题」列表,每条含标题,可直接「去创作」或删除,不再仅存在于对话输出中。

## 8. 既有交付文档的条目说明

- **口径提示**:数据统计口径,即各指标的计算标准。例如"热度"取播放量与点赞量的较高值;视频号不公开播放量,按点赞量折算。以界面灰色辅助文字为准。
- **封面**:封面生成工作流(参考图 + 标题合成)的原理说明,实际使用在创作流程「封面」步骤内完成。
- **运维表**:端口、目录、日志路径等维护信息,面向维护人员,日常使用无需关注。

配置项逐条说明见《02-系统全参数配置对照表》;报错对照见《03-常见报错排查手册》。仍有不明确的条目,标注后反馈,将按条补充说明。
