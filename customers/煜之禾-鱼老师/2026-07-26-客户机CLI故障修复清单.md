# 爆创 · 客户机故障修复清单（2026-07-26）

**机器**：鱼老师 Windows 笔记本（LAPTOP-46DD8M7P，Win11）
**现象**：软件里「本地 CLI 智能体」一个都扫不到，claude、codex 都不显示

---

## 一句话结论

**不是软件坏了，也不用重装。** 是这台电脑上三处系统层面的问题叠在一起，已全部修好并当场验证通过。

---

## 查出来的三个问题

### 1. Windows 系统 PATH 被写坏了

系统环境变量 `Path` 里本该是 `%SystemRoot%\system32`，实际被写成了 `%Sys;emRoot%\system32`——一个字母变成了分号。

后果：`cmd.exe` 这个 Windows 最基础的程序都找不到。而 claude、codex 这类工具在 Windows 上都要经 `cmd.exe` 启动，所以它们一起从列表里消失了。

> 旁证：不经过 `cmd.exe` 的 hermes 当时还在列表里——这正是定位问题的关键线索。

**已修**：修复注册表并保住原有类型，旧值已备份到 `C:\Users\Alice\path-backup-20260725-224236.txt`。

### 2. claude 其实没装完（只有 500 字节的空壳）

新版 npm 默认会拦截安装脚本，而 claude 恰好是靠安装脚本下载真正的程序本体。结果 `claude.exe` 只有 **500 字节**，运行时报「此版本与你运行的 Windows 版本不兼容」——**看着像系统不兼容，其实是根本没装完**。

**已修**：用放行安装脚本的方式重装，现在是完整的 265MB 本体，`claude --version` 正常返回 `2.1.220`。

### 3. 改完系统设置没重启，等于没改

Windows 里每个程序的环境变量是**启动那一刻的快照**。桌面进程（explorer.exe）从 7/25 19:39 起就没重启过，而 PATH 是 22:42 才修的，所以从桌面点开的爆创拿到的仍然是那份坏掉的旧设置。

**已修**：重启了桌面进程，新的设置已生效（正常做法是注销重登或重启电脑，效果一样）。

---

## 附带修好的：hermes 智能体

检查时发现 hermes 也是坏的，而且软件当时默认选中的就是它——等于选了一个跑不起来的智能体。

两处问题：

1. hermes 的 Python 环境指向了一个**不可访问的目录链接**（Windows 出于安全策略拒绝穿过它），导致任何 hermes 命令都起不来；
2. hermes 的 ACP 通信组件从来没装上。

**已修**：重建目录链接 + 补装组件。现在 `hermes --version` 与 `hermes-acp --version` 都正常。

## 下一版软件会带的改进

这次的根因虽然出在电脑的系统设置上，但软件本身也有可以做得更稳的地方，已经改好，随下一版更新自动生效：

1. **系统设置坏了也能扫到智能体**——软件启动智能体时会自带 Windows 关键环境信息，并用绝对路径调用系统程序，不再依赖 PATH 是否健康。今后遇到同类电脑，不用再改注册表。
2. **不会再显示"假的可用"智能体**——像 hermes 那种能启动却跑不起来的情况，以前会被显示成可用甚至被自动选中，现在会如实标为不可用，不会再让人选到一个用不了的。
