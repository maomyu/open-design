■ 3.1 apps/daemon/src/media-studio/bakuan-engine.ts(核心,+62 行区改动)

  【平台化】新增三个集中常量/助手,杜绝调用点散写 platform 判断:
    - IS_WIN = process.platform === 'win32'
    - VENV_BIN_DIR = IS_WIN ? 'Scripts' : 'bin'
    - exeName(name) = IS_WIN ? `${name}.exe` : name
  逐点替换:
    a) handleFor():venv 目录 .venv/bin → .venv\Scripts;
       python → python.exe;yt-dlp → yt-dlp.exe;
       POSIX 兜底 PATH(/opt/homebrew/bin 等)win 下不再拼入
    b) provision():内置 Python 入口
       POSIX: <runtime>/python-runtime/bin/python3
       WIN  : <runtime>\python-runtime\python.exe
       (python-build-standalone 两平台目录布局本就不同)
    c) ffmpeg 解压标记 ffmpeg/ffmpeg → ffmpeg\ffmpeg.exe
    d) pip 路径 .venv/bin/pip → .venv\Scripts\pip.exe
    e) ensureLarkCli() 解压标记 lark-cli/lark-cli → lark-cli\lark-cli.exe

  【bug 修复 1:tar 盘符】新增 tarBinary():win 钉死
    C:\Windows\System32\tar.exe(bsdtar,Win10 1803+ 自带;不存在再退回裸 'tar')。
    原因:裸 'tar' 在本机解析到 PATH 里 Git 的 GNU tar,GNU tar 把
    "C:\..." 的冒号当 host:path 远程传输语法,解压 python-runtime.tar.gz 直接
    "tar: Error is not recoverable: exiting now"——第一次装机首启 provision
    实测就是这么失败的(daemon 日志抓到)。bsdtar 原生支持盘符路径。
    客户机若装了 Git/MSYS 同样会踩,故必须钉死而不是依赖 PATH 顺序。

  【bug 修复 2:GBK,配合 §3.3】handleFor() 返回的引擎子进程 env 增加
    PYTHONUTF8='1' + PYTHONIOENCODING='utf-8':
    - 让引擎内所有 subprocess text 解码、print 中文输出默认走 UTF-8
    - POSIX 上本就是 UTF-8,零副作用

  【新导出】ensureLarkCli(改 export)、larkCliRuntimeDir(新增):
    供 server.ts 连接飞书流程复用(见 §3.2)

■ 3.2 apps/daemon/src/server.ts(+26 行区改动)

  「连接飞书」流程 6 处 lark-cli spawn 全部接入新助手 larkCliSpawnEnv():
    1) larkCliInstalled()            : lark-cli --version(装机自检)
    2) feishuProfileConnected()      : auth status --profile baochuang-client
    3) feishuAppConfigured()         : auth status(查 appId)
    4) feishuStartUserLogin() exec   : auth login --no-wait(拿链接+设备码)
    5) feishuStartUserLogin() spawn  : auth login --device-code(后台轮询)
    6) config init spawn             : config init --new(建应用引导)
  larkCliSpawnEnv() 行为:
    - 先 ensureLarkCli(幂等解压自带二进制;失败静默退回系统 PATH)
    - packaged 下把 <dataDir>\engine-runtime\lark-cli 放 PATH 最前
    - dev 下(resourceRoot=null)原样返回 process.env,行为不变
  意义:此前自带 lark-cli 只注入引擎 Python 子进程的 env,daemon 自己 spawn 的
  连接流程用裸 PATH——客户机基本没装 lark-cli,UI 会误报「未检测到 lark-cli」,
  连接飞书这一步整条死路。win 上 spawn('lark-cli') 由 CreateProcess 自动补 .exe,
  目录进 PATH 后即可命中。mac 包同样受益(同样的缺口)。

■ 3.3 bakuan-engine/ 7 个 Python 文件(GBK 解码崩溃修复,即你报的建表失败)

  根因链(实测复现确认):
    中文 Windows ANSI 码页 = GBK(cp936)
    → subprocess.run(..., text=True) 默认用 locale 编码(GBK)解码子进程输出
    → lark-cli 输出 UTF-8 JSON(含中文表名/提示)
    → 读线程 UnicodeDecodeError: 'gbk' codec can't decode byte 0xaa
    → 线程死掉,CompletedProcess.stdout = None
    → provision_datacenter.run() 里 json.loads(r.stdout)
    → TypeError: the JSON object must be str, bytes or bytearray, not NoneType
    (= 你界面上看到的那个报错;真实的 lark-cli 输出被这层崩溃完全掩盖)

  修复(9 处 text=True 全部补 encoding="utf-8", errors="replace"):
    - src/feishu/larkcli_bitable.py  : _run() 两处(主跑 + --format json 重试)
    - src/pipeline.py                : 1 处(206 行子进程调用)
    - scripts/provision_datacenter.py: run()(建表主通道)
    - scripts/wipe_tables.py         : 1 处
    - scripts/convert_field_types.py : 1 处
    - scripts/feishu_bot.py          : 2 处(messages-send + event consume 长驻流)
    - scripts/browser_collect.py     : 1 处
  防御加固(以后同类故障能看到真实报错,不再被 TypeError 淹没):
    - provision_datacenter.run(): json.loads(r.stdout or "");
      异常兜底拼接改 (r.stdout or "")[:200] + (r.stderr or "")[:200]
    - larkcli_bitable._run(): 报错文案拼接同样 (r.stdout or '')[:120] 化
  发布方式:引擎源码随包发布,老装机由 daemon 的 resync 机制
  (源码版本戳比对)自动同步进 <dataDir>\bakuan-engine,无需重装。

4) ffmpeg.tar.gz(约 106 MB)
   来源: github BtbN/FFmpeg-Builds latest,ffmpeg-master-latest-win64-gpl.zip
   加工: 只取 ffmpeg.exe + ffprobe.exe(引擎 ASR 抽音频 + yt-dlp 合流够用,

5) lark-cli.tar.gz(约 12 MB,内含 44 MB 原生 exe)—— 即「飞书 CLI」

   实测: lark-cli.exe --version → "lark-cli version 1.0.72" 正常
   (mac 机 vendor 是 v1.0.59,同一来源,win 直接取当前最新)

八、「飞书建表失败」完整故障处理记录(你使用中报的问题)
--------------------------------------------------------------------------------
现象   : UI 建表报 TypeError: the JSON object must be str, bytes or bytearray,
         not NoneType(栈落在内置 python-runtime 的 json/__init__.py:339)
