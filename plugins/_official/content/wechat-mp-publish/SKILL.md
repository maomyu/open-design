# 公众号长文发布总控

把一个选题做成一篇可发布的公众号长文,经过 选题 → 写稿 → AI 检测 → **自动排版** →(可选)配图 → 发到草稿箱,全程驱动本机「多媒体自动发布」工作台的现成技能,你只负责**编排 + 维护右侧数据看板(`board.json`)**。**写完稿不必等我确认,直接排版;排好版后再问我要不要配图。** 最后**只发到草稿箱**,正式群发由用户在公众号后台自己点。

## 工作台(所有能力都在这儿)

- **统一约定:所有内置插件驱动的外部工作台都是 `~/.open-design/workbenches/` 下的一份独立拷贝**(可用环境变量 `OD_WORKBENCH_DIR` 改根;先在 shell 里解析根:`WB="${OD_WORKBENCH_DIR:-$HOME/.open-design/workbenches}"`)。**别写死任何深路径,也别回头去用原位置——优化都在工作台这份拷贝上做。**
- **本插件的工作台 = `$WB/多媒体自动发布`**(下文叫「工作台」)。它的 `.claude/skills/MY-wechat-*` 是各环节方法论、`.venv` 跑脚本、`MY-wechat-shared/.env` 放凭据、`MY-wechat-shared/scripts/` 放脚本、`archives/{date}/` 收产物。(若该目录不存在,如实告诉用户把工作台拷一份到 `$WB/多媒体自动发布`,别去别处乱找。)
- **每个环节先读工作台对应的 `MY-wechat-*/SKILL.md` 再照它做**(写作风格、API 调法、配图脚本参数都在里面,别自己另发明)。
- **Python 一律用工作台的 `.venv`**:`WB="${OD_WORKBENCH_DIR:-$HOME/.open-design/workbenches}"; cd "$WB/多媒体自动发布" && ./.venv/bin/python3 .claude/skills/MY-wechat-shared/scripts/<脚本>.py ...`(系统 Python 有 SSL 偶发问题)。
- **凭据由 social-auto 注入到环境变量**(`os.environ`),脚本直接读即可,**不用、也别去改工作台的 `.env` 文件,更不要手动设置/覆盖任何凭证变量**。分两类:**公众号凭证(WECHAT_APPID/SECRET/AUTHOR)按「选定账号」自动注入**——它们只来自账号档案,插件级配置和工作台 .env 对这几个键一律无效;缺了就如实告诉用户去「编辑插件 → 账号」给该账号补,**绝不换账号重试**。其它 API key(DAJIALA/QWEN/GEMINI)仍来自「插件配置」,缺哪个就引导去「编辑插件 → 插件配置」填(`od plugin config wechat-mp-publish` 也行),别瞎找、别假装有。
- **产物落当前 Open Build 项目目录**:配图存项目里的 `3-配图/`(board 的「配图」表用项目内相对路径引,宿主渲成缩略图);排好的公众号 HTML 存 `4-排版-article.html`(可在右侧当成单独文件预览);草稿正文等也留项目里。工作台 `archives/{date}/` 只是可选备份,**别写 /tmp**。

## 右侧看板 = 一个 `board.json`(结构化数据,不是 HTML)
<!-- od:display=table -->
> **交互在左侧对话,展示在右侧数据看板(`od:display=table`)。** 右侧看板由宿主按项目里的 `board.json`(多维表格式的结构化数据)渲染成**只读表格**——**你只插数据 / 改数据,绝不写 HTML/CSS**(每步生成 HTML 是右侧变慢的根源)。每次要用户拍板,都用 **AskUserQuestion** 在左侧弹选项卡(自带「补充建议」框,用户点选项 + 写一句想法一起提交)。

**维护项目目录下的一个 `board.json`,固定下面这套表。** JSON 形状(严格照这个,顶层用 `tables`、不是 `bases`):
```json
{ "title": "公众号发布", "steps": ["选账号","选题","写稿","排版","配图","发草稿"], "step": 1,
  "tables": [ { "name": "选题候选",
    "fields": [ {"key":"标题","name":"标题","type":"text"},
                {"key":"热度","name":"热度","type":"select","options":[{"value":"高","color":"green"}]},
                {"key":"查看原文","name":"查看原文","type":"link"} ],
    "rows": [ {"标题":"...","热度":"高","查看原文":"https://..."} ] } ] }
```
`field.type` ∈ text/longtext/number/select/link/image/checkbox/progress/date;`select` 的 `options` 用 `[{value,color}]`(color: green/amber/red/blue/grey);`rows` 每行用**字段名**当 key。**每步往对应表插行 / 改单元格——优先用 Edit 改一格、加一行(极小、极快);把 `step` 设成当前步(从 1 开始),步骤条会高亮。**

- `title`: `公众号发布`;`steps`: `["选账号","选题","写稿","排版","配图","发草稿"]`(注意:**排版在配图之前**——写完稿先排版,再问要不要配图);`step`: 当前第几步。
- 表 **选题候选**:字段 `标题`(text)/`角度`(text)/`热度`(select 高·中·低)/`相关`(select)/`差异`(select)/`来源`(text)/`查看原文`(link)。选题步插入候选行,每条都填来源 + 查看原文(原文 URL)。
- 表 **文章**:字段 `标题`(text)/`正文`(longtext)/`标签`(text)/`皮肤`(select)/`状态`(select 草稿·已定稿)。写稿步写这一行,排版步更新皮肤/状态。**正文放 longtext,别往对话里整段复述。**
- 表 **配图**:字段 `位置`(text,如 封面/图1)/`描述`(text)/`图片`(image,项目内相对路径如 `3-配图/封面.jpg`)/`状态`(select 成功·失败)。配图步每张一行。
- 表 **发布**:字段 `项`(text)/`状态`(select)/`详情`(text 或 link)。发草稿步写「草稿状态」「草稿链接」等行。
- **select 上色**用字段的 `options`:成功 / 已定稿 / 已发草稿 = `green`;进行中 / 草稿 = `amber`;失败 = `red`。
- **首步先 Write 整个 `board.json`**(含这四张表的 `fields` + 空 `rows`),之后每步只 **Edit** 插行 / 改格,**别整文件重写**。

## 每步怎么问(AskUserQuestion)
**所有"选 / 改 / 确认"都用 AskUserQuestion**(卡片自带「补充建议」框,用户选完还能写一句想法一起提交)。按场景:
- **A 一次性选择 / 确认**:选题选哪个候选、「确认发到草稿箱 / 重做这步」——给 2–4 个选项让用户点;要补充就写补充框。
- **B 多项设置一起问**:开场若方向空缺,用 AskUserQuestion 补问;自由文本(如具体方向)让用户写补充框,别替他捏造。
- **写完稿不问、直接排版**:写稿这步**不要**用 AskUserQuestion 停下问「这版怎么处理」——写完(查完 AI 腔)直接进排版步自动排版,让用户在右侧 `4-排版-article.html` 上看排好版的成品。
- **C 提修改建议、驱动你改(在排好版的成品上)**:**排版完成后**,用 AskUserQuestion 问「排好版了(右侧 `4-排版-article.html`),要不要配图?」给 `要配图 / 不用,直接发草稿`——用户若要改内容就把改法写补充框(如「第二段太啰嗦/标题换一个」),你照着 Edit「文章」表的正文那一格、重排,再问。**默认「提建议→你改」,不是让用户自己写终稿。**
- **排版皮肤绝不问**:见全局铁律——皮肤是插件设置里已选好的固定项,写完稿后直接照它排版,不要用 AskUserQuestion 问用户「用哪个皮肤 / 换不换皮肤」。
- **来源 / 查看原文**:放「选题候选」表的 `查看原文`(link)字段(原文 URL),宿主自动渲成可点的新标签链接——**选题这一步每个候选都要带来源 + 原文链接**,让用户点进去自己判断溯源。只放 http/https。

## 开场 + 步骤条
- **第 0 步先定账号(前置)**:本插件按「账号」区分写作风格。**开场输入里已带账号(对话框的「公众号账号」下拉,选项来自插件编辑页「账号」区)就直接用它,绝不复问**;只有账号为空,才用 AskUserQuestion 在系统提示「账号（前置）」列出的已配置账号里让用户单选。选定后写稿严格按该账号的风格;**发布凭证由系统按选定账号自动注入,你无需(也不要)做任何凭证设置**。一个账号都没配就提醒用户去插件编辑页「账号」区先建一个再开工。
- **开场消息已带用户填的设置**(选题方向 / 排版皮肤 / 发布通道;文章类型固定为信息服务攻略):先读它,已给的别再从零问;只有某项空着 / 还是 `{{...}}` 占位符,才用 AskUserQuestion 补问那一项。
- **步骤条 = TodoWrite**:开工先写 6 步 `选账号 / 选题 / 写稿 / 排版 / 配图 / 发草稿`(账号在最前、排版在配图之前),每步 in_progress→completed(与 board 的 `step` 同步)。

## 全局铁律
- **写完稿直接自动排版(不停下确认),排版后才问配图**:顺序是 **写稿 → 排版 →(可选)配图 → 发草稿**。
  - 写稿这步**写完(查完 AI 腔)别用 AskUserQuestion 停下问确认**,直接进排版。
  - 排版皮肤由插件设置里的 `skin` 输入选定(用户已选好的固定项,不是运行时再挑),**直接用它排版,绝不问用户确认或换皮肤**。先排**纯文版**(此时正文里的 `<!-- IMAGE_N -->` 只是占位、还没图):用 MY-wechat-html-render 排成全内联 CSS 的公众号 HTML,存 `4-排版-article.html`,把「文章」表那行 `皮肤`=该皮肤、`状态`=已排版。
  - **排好版后,用 AskUserQuestion 问「排好版了,要不要配图?」**(`要配图 / 不用,直接发草稿`;要改内容写补充框)。要配图→进配图步生成图并**重排**(把图以项目内相对路径插回 `4-排版-article.html`);不用→直接进发草稿。**配完图立刻进发草稿步把草稿发出去,不要再停下问别的**(自动模式下「要不要配图」也不问:有 `<!-- IMAGE_N -->` 就配,没有就直接发)。
  - 用户要换排版风格,改插件输入重跑即可。
- **所见即所发(草稿必须和预览一致)**:`draft/add` 的 content **只能来自 `4-排版-article.html`**,除图片 src 替换外一个字不改、绝不重新排版。发布时内图逐张 `uploadimg`,**每拿到 mmbiz URL 就替换掉 content 里对应的本地 src**(残留本地路径=那张图必丢);封面 `add_material`(没配图也要兜底封面)。提交前自检:全部 img 为 mmbiz / 开头无 H1 大标题(标题只进 `title` 字段)/ **无 `<ol>/<ul>/<li>`(微信剥序号,序号必须是排版时手写进 `<p>` 的文本)** / title ≤64 字节。
- **只发到草稿箱**(`draft/add`)。正式群发由用户去公众号后台自己点;**绝不自动正式发布、绝不谎报已发**。
- **写作风格固定为信息服务攻略**(`MY-wechat-writer-service`,把一件事讲清楚:是什么/适合谁/怎么做/多少钱/什么时候),不再按题材切换其它风格。
- **用户可见输出(对话/board/确认问句)永远不带价格**,二次确认只说条数/页数。
- Python 必须用工作台 `.venv`;凭据由「插件配置」注入环境变量、脚本读 `os.environ`(别去读/改 `.env`);**配图等脚本的输出目录指到当前项目目录**(如项目里的 `3-配图/`),工作台 `archives/{date}/` 仅留可选备份。
- 任何环节能力不具备(缺 key / IP 没白名单 / 接口失败)→ 优雅降级 + 一句话说明(写进「发布」/对应表的状态),绝不反复重试报错、绝不假装成功。
